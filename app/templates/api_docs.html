API Documentation

Everything you need to call PrediQt's prediction and webhook endpoints directly from your own code.

Authentication

Every request must include your API key in an Authorization header, using the Bearer scheme. Generate a key on the API Keys page.

Authorization: Bearer pq_live_8f3K9xAB...

Requests without a valid key return 401 Unauthorized. Keys created in Test mode score transactions normally but never save predictions to your Dashboard or Alerts — safe for trying things out.

POST /api/v1/predict

Scores a single transaction. Requires the Predict scope on your key.

Request body
{
  "transaction_type": "card_purchase",
  "amount": 450.00,
  "hour": 14,
  "is_weekend": 0,
  "merchant_category": 2,
  "is_international": 0,
  "is_new_merchant": 0
}

Only amount is required — every other field has a safe default. Some fields are model-specific: gender, age, geo_distance for Credit Card transactions; old_balance, new_balance for Mobile Transfer types. transaction_type determines which specialist model handles the request.

Example request
curl -X POST https://yourdomain.com/api/v1/predict \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"transaction_type": "card_purchase", "amount": 450.00, "hour": 14}'
Response
{
  "label": "LEGITIMATE",
  "probability": 0.09,
  "risk_level": "LOW",
  "model_used": "Credit Card Fraud Model",
  "test_mode": false
}

POST /api/v1/batch

Scores every row in an uploaded CSV. Requires the Batch scope on your key. Send as multipart/form-data, not JSON.

Example request
curl -X POST https://yourdomain.com/api/v1/batch \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "transaction_type=card_purchase" \
  -F "file=@transactions.csv"
Response
{
  "total": 500,
  "fraud": 12,
  "legitimate": 488,
  "test_mode": false,
  "results": [
    {"row": 1, "fraud_probability": 0.0421, "risk_level": "LOW", "result": "LEGITIMATE"},
    {"row": 2, "fraud_probability": 0.8817, "risk_level": "HIGH", "result": "FRAUD"}
  ]
}

The CSV needs at minimum an amount column. Additional columns (hour, is_weekend, merchant_category, etc.) improve accuracy but are optional.

Rate Limits

Each key is limited to {{ rate_limit }} requests per day, resetting at midnight UTC. The limit applies per key, not per account — multiple keys on one account each get their own allowance.

Webhooks

Instead of polling, you can have PrediQt push data to your own server the moment something happens. Set these up on the Webhooks page.

Events
EventFires when
fraud.detectedAny single prediction (via the dashboard or /api/v1/predict) is flagged as FRAUD
batch.completedA batch upload finishes with at least one fraud case found
Verifying the signature

Every webhook payload is signed with HMAC-SHA256 using your webhook's secret, sent in the X-PrediQt-Signature header. Verify it before trusting the payload:

import hmac, hashlib

def verify_signature(payload_body, signature, secret):
    expected = hmac.new(secret.encode(), payload_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
